Kotlin 源码目录为 `app/src/main/java/com/tyverse/smswebhook/`。Room 首版使用单个 messages 表保存短信及其单个投递任务，避免在第一版引入多接收端关联表。已导出 schema，正式发布之后修改结构必须增加版本和迁移，不能使用破坏性重建替代迁移。

使用 Android 自带 JSONObject 构造 JSON，正文在落盘时固定并加密保存；首版没有引入设计文档中的 kotlinx.serialization。尝试次数、最近状态和错误持久化在消息记录中，尚无独立的每次尝试历史表。

## 可靠性实现

- Receiver 使用 goAsync，在有界后台操作中解析并落盘，不在接收器里等待 HTTP 或 Root 授权。
- 原始 PDU、设备安装标识与可用订阅信息计算指纹，数据库唯一约束去重；不只按正文去重。
- Worker 每条消息领取随机租约，完成时匹配租约，防止旧执行者覆盖新状态。
- 记录墙钟、单调时钟和启动次数，恢复超时或跨重启遗留租约。
- Room 与 WorkManager 入队之间的缺口由应用启动、开机/应用更新广播和周期恢复任务修复。
- 发送前固定目标快照，手动迁移到新配置需要明确操作。
- 使用至少一次投递；服务端幂等仍是端到端防重复的必要条件。
- 失败退避与 Retry-After 在数据库中持久化，系统实际调度可能进一步推迟执行。
- 正文、payload、目标认证和签名密钥加密；禁止自动备份和设备迁移这些应用数据。

## 参考项目的使用方式

本地参考：`tmp/SmsForwarder`；上游为 [pppscn/SmsForwarder](https://github.com/pppscn/SmsForwarder)，本地 LICENSE 为 BSD-2-Clause。核心实现独立编写，没有直接复制其业务源码，下面是针对本地源码进行的比较，不是对上游最新版本的认证。

| 参考模块 | 借鉴点 | 本项目取舍 |
| --- | --- | --- |
| `receiver/SmsReceiver.kt` | 系统短信广播、分段处理、订阅信息 | 先落盘再安排发送；缺失订阅标记未知，不将 slot/simId 当成订阅 ID |
| `workers/SendWorker.kt` | 接收、规则和发送分层 | Receiver 完成最小安全落盘，Worker 发送；加数据库领取和幂等机制 |
| `database/entity/Rule.kt` | 发送方、包含和排除等匹配方式 | 首版提供白名单与包含/排除文字，限制规模，暂不引入正则和复杂表达式 |
| `entity/setting/WebhookSetting.kt` | 独立的发送配置与认证 | 首版 JSON POST + Bearer/HMAC；多方法、自定义模板和代理后续按需增加 |
| `utils/KeepAliveUtils.kt` | 电池优化状态检查与设置引导 | 增加 Root 白名单操作及只撤销自身变更的记录 |
| `receiver/BootCompletedReceiver.kt` | 重启后的恢复入口 | Android 16 上恢复队列，不在开机广播里直接启动 Activity |
| `service/ForegroundService.kt` | 故障可见性和后台状态管理 | 不引入与短信无关的定位、音频、内网穿透服务，保持当前后台任务有界 |

未把参考项目的通话、通知监听、发送短信、远程短信指令等功能纳入本项目权限和开发范围。

## 验证

最终开发版已通过以下检查，包含新增过滤规则和无障碍调整：

- Debug APK 构建通过。
- 未签名 Release APK 构建通过，包含 Worker 和 ViewModel 的 R8 保留规则。
- 原有及新增单元测试 42 个通过，覆盖重试、日期解析、签名、URL 校验、指纹边界及过滤规则。
- Android 16 / API 36 模拟器上的 13 个设备测试通过，包括数据库并发、加密、响应处理和 Compose 设置页发出真实 HTTP 请求。
- Lint：0 errors，24 warnings，主要是依赖更新、模板资源与按用户要求使用 target 36 的提示；没有隐藏或通过 baseline 屏蔽错误。
- 新增的 12 个过滤规则单元用例已包含在上述 42 个中，全部通过。

Android 16 模拟器人工端到端检查：

1. 注入系统模拟短信，接收端收到 source=sms_broadcast 的请求。
2. 确认应用进程已经不存在后注入短信，应用被系统重新启动并成功发送。
3. 接收端为新任务首次返回 500，之后相同 delivery_id 第二次请求成功。
4. 关闭模拟器 Wi-Fi 与移动数据，确认无活动默认网络；注入短信后退出应用进程，恢复网络后成功补发，未重新打开界面。
5. 在设置页保存发送方白名单，验证不匹配的模拟短信未发送、匹配短信成功发送；诊断页显示过滤次数 1 和“发送方不在白名单”。
6. 无 su 的模拟器中点击 Root 检测，正确显示 Root 不可用，标准收信和投递仍可使用。此项不能替代真实 Root 设备测试。

最终 APK 的 Manifest 已检查：minSdk 26、targetSdk 36、allowBackup=false。Debug APK 使用调试签名，可安装；Release 文件未签名，只完成了构建验证。

所有请求都发送到电脑本机测试服务，没有发送到第三方服务，也没有处理真实手机短信。上述进程退出使用调试进程终止，不代表已经验证厂商全部杀后台情形。

## 界面约定

使用 Material 3、系统字体、浅/深双主题和青绿色状态色，四项底部导航。状态同时有文字，不只靠颜色；正文默认隐藏，按钮保留原生触控尺寸，筛选条件允许换行。

界面设计参考 ui-ux-pro-max 的运维监控信息层级与可访问性准则；其 Compose 专项查询未找到适合的条目，实际组件按原生 Material 3 实现和设备测试验证，不套用网页落地页模板。
