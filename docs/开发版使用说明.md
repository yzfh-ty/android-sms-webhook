# 开发版使用说明

版本：0.1.0。主要目标设备：Android 16。应用包名：`com.tyverse.smswebhook`。

## 1. 安装和首次配置

使用 Android Studio 的 Run 安装开发版，或者安装 `app/build/outputs/apk/debug/app-debug.apk`。开发版已使用调试签名，Release 构建文件尚未配置发行签名。

应用默认关闭短信转发，按以下顺序设置：

1. 进入“设置”，填写完整 Webhook URL。
2. 接收端需要 Bearer 认证时填写 Token；需要本项目 HMAC 协议时填写签名密钥。
3. 点击“保存并发送测试”。这会保存当前地址、认证与过滤规则，然后创建独立测试通知。
4. 进入“记录”，查看测试通知是否“已接受”。认证失败等永久错误会显示“需处理”。
5. 通过概览或诊断页面授予“接收短信”权限，开启转发开关。
6. 需要故障提醒时授予通知权限；该权限不影响短信接收授权本身。

应用不要求成为默认短信软件，不申请发送短信或读取历史短信权限。安装器、ROM 或系统短信保护仍可能影响 RECEIVE_SMS 授权和实际广播投递。

## 2. Webhook 格式

当前支持通用 UTF-8 JSON POST，不内置钉钉、企业微信等专有消息模板。接收端示例：

```json
{
  "schema_version": 1,
  "event_id": "stable-message-uuid",
  "delivery_id": "stable-message-uuid",
  "device_id": "installation-uuid",
  "source": "sms_broadcast",
  "sender": "10086",
  "body": "短信正文",
  "sms_timestamp": "2026-10-29T08:00:00Z",
  "received_at": "2026-10-29T08:00:01Z",
  "subscription_id": null
}
```

首版单接收端的一条短信对应一个投递任务，因此 event_id 与 delivery_id 使用同一个 UUID。测试通知的 source 为 `test`。subscription_id 是系统订阅 ID，不是卡槽编号；无法获取时为 null。

请求头：

```text
Content-Type: application/json; charset=utf-8
Idempotency-Key: <delivery_id>
X-SMS-Timestamp: <本次请求的 Unix 秒数>
Authorization: Bearer <可选 Token>
X-SMS-Signature: v1=<可选 HMAC-SHA256 的小写十六进制结果>
```

签名输入为 UTF-8 编码的 `timestamp + "." + 原始请求体`。重试时任务 ID 和正文保持不变，时间与签名重新生成。接收端需要验签、检查时间偏差，并按 Idempotency-Key 持久去重。

2xx 表示接收端已接受。当前不解析任意服务商响应中的业务状态，也不跟随重定向。服务端可能已经处理了超时请求，随后客户端仍会重试，因此接收端必须正确处理重复请求。

## 3. 过滤规则

在“设置”下方配置，点击“保存过滤规则和配置”生效：

- 发送方白名单：完整匹配实际收到的发送方，每行一个；不同国家区号不会自动视为同一个号码。
- 包含关键词：正文包含其中任意一行即可。
- 排除关键词：命中任意一行直接跳过，优先于白名单和包含条件。
- 同组为“或”，白名单与包含条件两组之间为“且”；空组不限制。
- 不区分英文字母大小写，使用普通文字匹配，不执行正则表达式。
- 每组最多 50 条，每条最多 128 字符，整个字段最多 6000 字符。

未匹配短信不保存正文、不创建投递任务。诊断页显示过滤触发次数和最后一次原因，不保存被过滤短信的内容。重复过滤广播可能重复计数，因此它是触发次数，不是去重后的短信数量。

测试通知不受过滤规则限制。规则修改只影响之后收到的短信，不重新筛选已经入队的任务。

## 4. 记录、暂停与重试

记录页显示最近 200 条，默认隐藏正文和部分长号码；点开详情查看完整内容、订阅 ID、目标地址和任务 ID。

| 状态 | 含义 |
| --- | --- |
| 待发送 | 已保存，等待网络与后台执行机会 |
| 发送中 | Worker 已领取任务 |
| 等待重试 | 连接失败、408、429 或 5xx，等待退避 |
| 已接受 | 接收端返回 2xx，不等于下游通知已经展示 |
| 需处理 | 认证/请求/安全错误，或自动重试达到限制 |
| 已暂停 | 收信开关关闭后保留的未完成短信任务 |

关闭转发会停止采集新短信并暂停未完成的短信任务。重新开启会恢复这些任务；停用期间不收集的新短信不会自动补回。显式发送的测试通知独立于收信开关。

每条任务保存创建时的接收地址和认证，普通修改设置不会改变旧任务。失败后可选择：

- 按原配置重试：保留原目标、认证和任务 ID。
- 改用当前配置重试：详情页确认后使用当前已保存的目标与认证。原接收端可能已经处理过消息，跨接收端无法保证业务不重复。

手动重试会重新开始自动重试窗口，但不更换任务 ID。默认最多自动尝试 20 次，窗口 7 天；实际执行时间受 WorkManager 和系统调度影响，页面时间表示最早执行时刻。

成功任务的正文、payload 和目标快照在成功尝试约 24 小时后清理，成功记录约 7 天后删除；失败与暂停记录不会按成功策略清理。可以手动清理全部已接受记录，未完成任务会保留。

## 5. 保活和 Root

应用使用 Manifest 短信接收器，界面无需保持打开。WorkManager 负责网络约束、重试和 15 分钟周期恢复检查；周期任务不保证精确定时。已保存任务在进程退出后可恢复，重启后首度解锁再恢复正常处理。

“诊断”提供：

1. 短信及故障通知权限状态。
2. 系统电池优化豁免状态和设置入口。
3. 通过 `su -c id` 检查 Root 授权。
4. 添加本应用的 deviceidle 白名单并确认结果。
5. 只撤销由本应用添加的白名单。
6. 手动检查队列、过滤次数和最近执行时间。

Root 命令有超时，拒绝或不可用时不影响标准收信模式。厂商的自启动、后台限制需要在实际手机设置。当前没有独立 Root 看门狗、Magisk 模块或长期空转前台服务。

“设置 → 强行停止”后需要用户重新打开应用；普通进程退出与强行停止不是同一情形。Root 也不代表绕过全部系统规则。

## 6. 模拟器联调

电脑安装已有 Python 后，在项目根目录运行：

```powershell
python tools/dev_webhook.py
```

Debug 应用填写：

```text
http://10.0.2.2:8765/hooks/sms
```

启动 AVD 后注入模拟短信：

```powershell
adb devices -l
adb -s emulator-5554 emu sms send 13800138000 "SMS webhook smoke test"
```

电脑查看测试服务状态：

```powershell
Invoke-RestMethod http://127.0.0.1:8765/state
```

测试服务只监听 127.0.0.1，仅在内存保存幂等状态，不打印正文和认证信息。`/hooks/flaky` 为每个新任务首次返回 500，之后返回 200；`/hooks/unauthorized` 固定返回 401。停止重启服务会清空其内存记录。

可选认证通过电脑进程环境变量 `SMS_WEBHOOK_TOKEN`、`SMS_WEBHOOK_SECRET` 设置，并在应用填写相同值。不要把实际密钥提交到仓库。

HTTP 只允许开发版访问 10.0.2.2、localhost 和 127.0.0.1；正式版需要有效证书的 HTTPS。手机上的 127.0.0.1 指手机自身，不是电脑。
