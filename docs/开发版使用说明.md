# 开发版使用说明

版本：0.3.2。主要目标：Android 16。正常包名：`com.tyverse.smswebhook`。

## 1. 配置企业微信群机器人

1. 在企业微信内部群中打开群机器人管理，添加机器人并复制 Webhook。
2. 在应用“设置”粘贴完整地址，包含末尾的 `?key=…`。
3. 点击“保存并测试”，在记录中查看结果。
4. 确认“已发送”后授予短信权限，并开启概览页的转发开关。

只需机器人地址，不再配置通用 Token 或 HMAC。地址是凭证，默认隐藏、加密保存；首页和任务详情只显示脱敏地址。

短信外发通道仅支持企业微信群机器人文本消息，不支持企业微信自建应用、个人微信、其他通知平台或任意通用 Webhook。eSIM 到期提醒另外支持手机本地通知。

## eSIM 卡片管理与续期

1. 打开底部“卡片”，点击“添加卡片”，手动填写名称、可选的运营商/识别信息及备注。
2. 选择具体到期日期和时间；卡片保存创建时的手机时区，之后手机切换时区不改变该卡的计算时区。
3. 设置续期周期，支持 1～3,650 天或 1～120 个日历月；月末续期自动取目标月最后一天。
4. 按卡设置提醒开关、提前量（天/小时）、是否重复及重复间隔。提前量为 0 表示到期时才提醒；重复默认关闭，开启后到期仍会继续提醒。
5. 按卡选择手机通知、企业微信或两者。手机通知需授权并开启“eSIM 到期提醒”通知渠道；企微提醒需先在设置中保存机器人。
6. 列表中每张卡都有“编辑卡片”，可直接修改已有资料。详情顶部固定显示“编辑卡片”和“已续期”，无需滚过长备注。保存后更新原卡，再次打开可查看修改；取消或放弃修改不改变原资料。完整备注和提醒结果在详情查看，备注和号码默认不发送到企微。
7. 实际续期后点击“已续期”，先核对确认弹窗中的周期和新日期，再点击“确认已续期”。取消不会修改资料。

**重新起算规则：新到期时间 = 确认时刻 + 本卡周期。** 不累加到旧到期日；提前操作可能缩短原有效期，弹窗会提示。续期后保留备注和提醒偏好，取消旧周期未发送提醒，其他卡片不受影响。

关闭短信转发不影响卡片提醒，短信过滤也不影响卡片提醒。仅改名称或备注不会重置已提醒标记。修改到期时间或提醒规则会重新安排提醒；删除卡片会停止该卡后续提醒。已发送的群消息无法撤回。

提醒依赖系统后台调度，可能延迟。长时间关机或停用后恢复，每卡只补发当前一次提醒，不集中发送所有历史时段。已存在未完成事件时先完成原事件，不叠加大量新消息。手机权限不可用时显示受阻状态，不当作提醒成功；企微失败可在详情或投递记录重试。

## 2. 消息和发送结果

群内文本示例：

```text
【短信通知】
发送方：10086
接收时间：2026-10-29 18:00:00
订阅 ID：1
编号：abcd1234

这里是短信正文。
```

发送格式：

```json
{
  "msgtype": "text",
  "text": { "content": "格式化后的短信通知" }
}
```

只有 HTTP 成功且响应中整数 `errcode` 为 0 才记为成功。响应缺失、无有效 JSON 或没有正确 errcode，不会误记成功。

| 返回 | 处理 |
| --- | --- |
| errcode 0 | 确认当前段成功 |
| errcode 45009 | 机器人过频，至少等待约一分钟后重试 |
| errcode -1 | 服务繁忙，按退避重试 |
| errcode 93000 | 机器人地址无效或已移出群，进入需处理 |
| 其他业务错误 | 保存错误码，进入需处理，避免持续轰炸 |
| 网络异常、408、429、5xx | 有界自动重试，保留待发送数据 |

不会跟随重定向，也不会跳过 TLS 证书校验。不发送通用 Authorization、HMAC 或 Idempotency-Key 请求头。

接口示例和错误处理参考 [腾讯 CloudBase 企业微信机器人说明](https://docs.cloudbase.net/recipes/connect-wecom-webhook-cloud-function)，完整接口见 [企业微信机器人文档](https://developer.work.weixin.qq.com/document/path/91770)。

## 3. 长短信、限频和重复消息

文本内容按每段最多 2048 UTF-8 字节处理，包含中文和 emoji 时按字节计算，不按字符数猜测。超长短信自动分段，每段包含编号和分段标识；不截断正文，也不拆断 UTF-16 代理对。

每段收到成功确认后持久化进度。后续段失败时，重试从尚未确认的段继续；进程退出后仍可恢复。所有段确认后，整条任务才显示“已发送”。

相同机器人 key 的任务共享持久化节流，发送间隔至少约 3.1 秒，配合过频错误退避，适应单机器人每分钟 20 条的限制。机器人如果还被其他工具使用，总发送频率仍可能超限。

**群机器人不提供客户端幂等保证。** 如果企业微信已收到一段，但响应丢失或客户端尚未保存确认便退出，重试可能重复。界面中的编号便于识别，不代表平台一定去重。

## 4. 过滤规则

在“设置”中展开“短信过滤”，修改后点击“保存过滤”：

- 发送方白名单：完整匹配实际发送方，每行一个。
- 正文包含关键词：任意一行匹配即可。
- 正文排除关键词：命中任一行便跳过，优先于其他条件。
- 同组为“或”，白名单与包含组之间为“且”；空组不限制。
- 不区分英文字母大小写，普通文字匹配，不执行正则。

每组最多 50 条，每条最多 128 字符，字段最多 6000 字符。未匹配的短信不保存正文、不创建投递任务；诊断页仅记录过滤触发次数和原因。测试通知不受过滤限制，规则修改不影响已入队任务。

## 5. 暂停、记录与手动重试

记录显示最近 200 条，正文默认隐藏。状态包括待发送、发送中、等待重试、已发送、需处理和已暂停；详情显示完整正文、订阅 ID、目标脱敏地址和任务编号。

关闭转发会停止采集新短信，保留并暂停未完成短信任务。重新开启会恢复这些任务；停用期间没有采集的短信不会自动补回。

每条任务绑定创建时的机器人，普通修改设置不会改变旧任务：

- 按原配置重试：保留机器人和已确认的分段进度。
- 改用当前配置重试：确认后更换目标；目标改变时重新发送全部分段，原群可能已收到部分消息。

手动重试重新开始自动重试窗口。自动执行最多 20 轮，默认窗口 7 天；系统调度可能进一步推迟执行。成功正文和目标快照约 24 小时后清理，成功记录约 7 天后清理；未完成记录不会按成功策略删除。

## 6. 从 0.1.0 升级

无需清空应用数据：

- 数据库执行 1 → 2 迁移，保留短信和投递状态，增加分段确认与企微错误码。
- 旧设置中的地址迁移为加密存储，旧 Token/HMAC 配置清除。
- 旧地址不符合企业微信机器人格式时，转发自动暂停并提示重新配置。
- 已完成任务不会重发。旧待发送内容在执行时转换为企微文本；不符合新通道的旧目标进入需处理，可明确选择改用当前机器人。

旧版完成记录显示“旧版完成”，不计入新版“已发送”数量，因为旧版没有验证企业微信业务状态。

## 7. 保活和 Root

Manifest 短信接收器无需界面常驻，WorkManager 负责网络约束、重试与周期恢复。系统重启后首次解锁恢复完整处理；强行停止后需要用户重新打开应用。

诊断页提供短信/通知权限、电池优化状态、系统设置入口、Root 授权检测、本应用白名单添加与撤销，以及队列检查。Root 不可用时仍能使用标准模式。

当前没有独立 Root 看门狗、Magisk 模块、Direct Boot 缓存或空转前台服务。实际手机仍需验证厂商自启动、省电和长期熄屏表现。

## 8. 本机模拟接口

```powershell
python tools/dev_webhook.py --mode ok
```

Debug 模拟器填写：

```text
http://10.0.2.2:8765/cgi-bin/webhook/send?key=local-test
```

可选模式：busy-once 首次返回服务繁忙；invalid-bot 返回机器人无效；rate-limit-once 首次返回过频。`GET http://127.0.0.1:8765/state` 仅提供计数和字节长度，不记录正文或 key，也不假装提供幂等去重。

该接口仅监听电脑本机。Release 不接受本地模拟地址；手机上的 localhost 指手机自身，不是电脑。
